# Household-supplies — система контроля домашних запасов

## 1. Назначение проекта
Household-supplies — учебное веб-приложение для учёта и контроля домашних запасов. 
Проект позволяет вести базу продуктов, бытовой химии и других товаров, отслеживать их количество, категории и владельцев. 

Проект развивается поэтапно: от консольного приложения и ручного SQL до полноценного веб-приложения на Django с использованием ORM и шаблонов.

## 2. Используемые технологии
- Python 3.x
- Django 5.x
- Django Template Language (DTL)
- Django ORM (Object-Relational Mapping)
- SQLite (база данных `db.sqlite3`)
- Bootstrap 5 (через CDN)
- HTML5, CSS3, JavaScript
- Git
- pytest, flake8, mypy, pylint

## 3. Предметная область и модели данных
В системе используются три основные сущности, представленные моделями Django:

### Category (Категория)
Группирует запасы по типам (например, «продукты», «химия»).
- `name` — название категории;
- `description` — описание.

### User (Пользователь)
Владелец запасов.
- `name` — имя;
- `email` — электронная почта.

### Stock (Запас)
Конкретный товар, принадлежащий пользователю.
- `name` — название запаса;
- `category` — внешний ключ (ForeignKey) на модель `Category`;
- `owner` — внешний ключ (ForeignKey) на модель `User`;
- `quantity` — текущее количество (FloatField);
- `unit` — единица измерения (кг, шт, л);
- `expiry_date` — срок годности (DateField, может быть пустым).

Связи между моделями реализованы через `ForeignKey` с параметром `on_delete=models.PROTECT` (защита от случайного удаления категории или пользователя, если на них ссылаются запасы) и `related_name="stocks"` для обратного доступа (`user.stocks.all()`).

## 4. Реализованные страницы и сценарии
- `/` — Главная страница с навигацией.
- `/stocks/` — Список всех запасов с постраничным выводом (пагинация по 5 записей), указанием категории и владельца.
- `/stocks/<id>/` — Карточка запаса с детальной информацией.
- `/categories/` — Список категорий.
- `/users/` — Список владельцев.
- `/users/<id>/` — Профиль владельца и список принадлежащих ему запасов.
- `/users/statistics/` — Статистика: количество запасов у каждого пользователя (с использованием `annotate` и `Count`).

## 6. Запуск проекта

1. Клонируйте репозиторий:
   ```bash
   git clone <адрес_репозитория>
   cd household-supplies
   ```

2. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv venv
   venv\Scripts\activate  # Для Windows
   ```

3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```

4. Примените миграции для создания базы данных и таблиц:
   ```bash
   python manage.py migrate
   ```

5. Запустите сервер разработки:
   ```bash
   python manage.py runserver
   ```

6. Откройте в браузере: `http://127.0.0.1:8000/`

## 7. Наполнение базы данных
База данных `db.sqlite3` создается пустой при применении миграций. 
Для переноса тестовых данных из предыдущей версии проекта (базы ПР7) используется скрипт:
```bash
python db/import_to_orm.py
```

## 8. Тестирование и проверка кода
- `python manage.py check` — проверка конфигурации Django.
- `pytest -v` — запуск автотестов.
- `flake8 . --extend-exclude=venv,migrations` — проверка стиля кода.

## 9. Текущее состояние проекта
- Реализован слой базы данных на основе **Django ORM**.
- Созданы модели `Category`, `User`, `Stock` и настроены связи.
- Управление структурой БД выполняется через **миграции**.
- Представления (`views.py`) используют ORM-запросы (`all()`, `get_object_or_404()`, `select_related()`, `annotate()`) вместо прямого SQL.
- Реализована пагинация списка запасов.
- Сохранен и работает веб-интерфейс на основе шаблонов Django (ПР6).
- Устаревшая реализация на SQL и JSON сохранена в папках `data/` и `db/` для истории.
